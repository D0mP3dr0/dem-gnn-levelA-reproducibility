# Provenance

This file lists, for every file in the repository, where it comes from, the evidence that it is the version
that ran or the record as written, the SHA-256 of that file, the SHA-256 of the file published here, and what
differs. `SHA256SUMS` carries the published digests in the format read by `sha256sum -c`.

## Sources and status

- **as run** (30 code files): the version that ran, identified by evidence: the run folder named in the
  `source_file` column of the records, the hyperparameters written by the runs, the header and content of the
  training logs, the compiled caches (`__pycache__`) next to the sources, and the dates of the sources against
  the dates of the records they wrote. The GNN runs date from 2025-12-31 (Amazonia, Pantanal), 2026-01-10
  (Mata Atlantica) and 2026-04-22 (Cerrado). `gnn/training/csv_logger_v18.py` and `gnn/training/module_v18.py`
  come from a copy of the run folder dated 2025-12-30, because the later copy writes eight log columns that no
  training log has and fills a metric that every log leaves at zero.
- **origin not identified** (5 code files): no copy could be shown to be the version that ran (each
  existing copy is dated after the records it wrote, or the compiled cache shows that a different version ran).
  The file published earlier is kept, with the same code.
- **record as written**: CSV and YAML records, from the earliest byte-identical copy.

The folder `cnn/` corresponds to the folder `src/` of the CNN run folder (`cnn/run_all_biomes.bat` calls
`python -m src.train`).

## Records and the scripts that wrote them

- The per-tile baseline records under `results/baselines/kriging`, `rf` and `cnn` (2026-04-26) have the column
  layout of a later evaluation harness that is not part of this repository; `baselines/02_run_kriging.py`,
  `baselines/05_run_rf_baseline.py` and `baselines/03_run_cnn_fair_eval.py` wrote earlier versions of these
  records. `results/baselines/gnn_official_fair_metrics.csv` is the output of `baselines/v21_gnn_fair_eval.py`.
- `analysis/t0_extract_all_metrics.py` wrote `cnn_all_epochs_timeseries.csv`; the best-epoch tables
  `gnn_best_epoch_all_metrics.csv`, `cnn_best_epoch_all_metrics.csv`, `gnn_all_epochs_timeseries.csv` and
  `reconciliation_train_vs_inference.csv` were then rewritten (2026-04-25) by a step that selects the best epoch
  by the minimum elevation MAE over all phases (`selection_criterion` = `min(elevation_mae) global`); that step
  is not part of this repository.
- `analysis/t1_full_analysis.py` wrote the `t1_*` and `t2_*` records; in `t1_6_generalization_lidar.csv` the
  rows of Cerrado and Mata Atlantica were later updated to the values of `gnn_best_epoch_all_metrics.csv`.

## What differs from the files as run or as written

- **Python sources.** Comments and docstrings were removed; string literals of four or more words (console
  messages, help texts) were translated into English and their emoji removed. The absolute data roots
  hard-coded in the scripts (a Google Drive folder on Colab and two local drive folders) were replaced by the
  variables `INTERNAL_DATA_ROOT` and `INTERNAL_GRAPH_ROOT`, read from `DEMGNN_DATA_ROOT` and `DEMGNN_GRAPH_ROOT`
  in one statement added at the top of each such script; private working-folder names inside paths became the
  generic folder name `internal`; in `analysis/t0_extract_all_metrics.py` one variable and one function name
  were given the prefix `INTERNAL_`. Twenty short strings (fewer than four words: console fragments and one label)
  remain as run, in Portuguese or with a symbol. `verify_code.py` recomputes the digest of each syntax tree with those parts
  normalized and compares it with the digest of the file as run, listed in `CODE_AST_SHA256`. The previously
  published `analysis/run_statistical_tests.py` did not parse; the file here is the version that ran.
- **`cnn/run_all_biomes.bat`.** The echo messages were translated; every other line is unchanged.
- **CSV records.** In `gnn_best_epoch_all_metrics.csv` and `cnn_best_epoch_all_metrics.csv` the local data-root
  prefix of the `source_file` paths became `${DEMGNN_DATA_ROOT}`; every other record is byte-identical.
  `verify_payload.py` recomputes the payload digest of each record and compares it with `PAYLOAD_SHA256`.

Because the bytes of the scripts changed, a digest of a script recorded elsewhere refers to the file as run;
the fourth column gives those.
